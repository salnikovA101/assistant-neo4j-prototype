# Neo4j Assistant

Это локальный прототип веб-приложения для работы с подключённой базой знаний
Neo4j. Пользователь задаёт вопрос в чате, приложение ищет связанные данные в
графе и формирует ответ с указанием найденных evidence и документов-источников.

Основная предметная область текущих корпусов — food science, микробиология и
умная упаковка. Приложение не ищет по открытому интернету: результаты зависят
от подключённой базы, её корпуса и настроек поиска.

Это не библиотека статей и не универсальный чат-бот. Приложение использует
графовую базу как источник предметных данных, а языковую модель — для
формулировки поисковых вопросов, отбора найденного контекста и подготовки
ответа.

## Как проходит запрос

1. Пользователь пишет вопрос в чате и указывает, что именно нужно найти,
   сравнить или проверить.
2. В режиме **Вопрос по базе** система сама формирует поисковые вопросы и сразу
   отвечает. В режиме **Исследование** эти вопросы сначала показываются
   пользователю, после чего поиск можно продолжать по выбранным направлениям.
3. Поисковый слой находит связанные сущности и связи в Neo4j, включая текстовые
   данные `evidence` и сведения об источнике.
4. Ассистент собирает найденные данные в ответ. Номера источников и граф данных
   позволяют посмотреть, на чём основан конкретный результат.
5. Результаты, варианты диалогов и выбранные данные сохраняются, чтобы к ним
   можно было вернуться или продолжить исследование позже.

## Что здесь есть

- FastAPI-сервер в `server/`.
- React/Vite-интерфейс в `web/`, который собирается внутри Docker-образа.
- Поиск по графу Neo4j через GraphRAG-пайплайн.
- SQLite для аккаунтов, истории чатов, вариантов диалогов, checkpoint и
  карточек.
- Промпты и пользовательское руководство в `prompts/`.
- Скрипты обслуживания и оценки в `scripts/` и `tests/`.

В интерфейсе доступны два основных режима: **Вопрос по базе** для отдельного вопроса и
исследование с накопительным списком исследовательских вопросов. Также есть
просмотр данных ответа на графе, ручной раздел «Вся база», варианты диалогов и
карточки по шаблонам, если они включены в конфигурации.

Раздел **Вся база** работает отдельно от чата: это ручной поиск по именам,
типам связей, источникам и `evidence`. Он не запускает ассистента и не меняет
граф. Найденные элементы можно временно собрать и вставить в новый запрос.

Карточки нужны для сохранения структурированного результата по шаблону. Их
можно заполнить по текущему диалогу, проверить и сохранить; пользовательские
карточки затем можно вставлять в другой вариант диалога как дополнительный
контекст.

## Где хранятся данные

- Neo4j содержит граф знаний, связи между сущностями и данные, на которые
  опирается поиск.
- SQLite хранит аккаунты, сессии, историю чатов, варианты диалогов, checkpoint
  и карточки.
- Настройки интерфейса и личный ключ модели хранятся в браузере текущей
  вкладки. Ключ не нужно отправлять отдельным сообщением в чат.

Подключённая база и её корпус задаются конфигурацией рабочей области. Поэтому
два пользователя или две рабочие области могут видеть разные данные при одном и
том же коде приложения.

## Важные ограничения

- Neo4j не запускается через этот Compose-файл и должен быть доступен отдельно.
- Для поиска нужны локальный Ollama с моделью эмбеддингов и настроенный LLM-провайдер.
- Голосовой ввод и озвучка присутствуют в коде, но по умолчанию выключены.
- Библиотека исходных статей пока находится в разработке; документы видны в
  источниках и данных графа, но отдельного просмотра полнотекстовых статей нет.
- Ответ ассистента не заменяет проверку исходных документов. Отсутствие данных
  в текущем корпусе не доказывает, что факта не существует.

## Минимальный запуск

Нужны Docker Compose, доступная база Neo4j и Ollama с моделью
`embeddinggemma:300m-qat-q8_0`.

```bash
cp .env.example .env
docker compose up --build -d
```

В `.env` нужно указать подключение к Neo4j, адрес Ollama для эмбеддингов и ключ
выбранного LLM-провайдера. После запуска интерфейс доступен по адресу
<http://localhost:8000/ui/>. Аккаунт для рабочей области создаётся командой:

```bash
docker compose exec app python -m server.manage_users create technologist --workspace packaging
```

Для локальной проверки кода используются обычные команды из корня репозитория:

```bash
python -m pytest tests -q
cd web
npm run build
```

## Где что искать

- `server/` — API, авторизация, состояние диалогов, поиск и интеграция с LLM.
- `web/` — клиентский интерфейс.
- `prompts/` — промпты режимов и справка для пользователя.
- `server/algorithm/README.md` — описание внутреннего retrieval-пайплайна.
- `docker-compose.yml` и `server/config.yaml` — запуск и основные настройки.

Подробное описание работы интерфейса, режимов, графа, карточек и типичных
проблем находится в [руководстве сервиса](prompts/service_guide.md). Этот же
файл используется интерфейсом как справка и может быть прочитан ассистентом,
когда пользователь спрашивает о работе с сервисом.
